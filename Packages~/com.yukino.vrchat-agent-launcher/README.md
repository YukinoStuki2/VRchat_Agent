# Yukino Agent Connection Manager — Windows 预览版

`com.yukino.vrchat-agent-launcher@0.1.0-preview.2`

Unity 菜单：**Tools → Yukino → Agent Connection Manager**。
ALCOM 管理窗口、监督程序及内置受限 Bridge 的安装和更新。**连接不等于编辑授权。**

## 首次准备

1. 备份工程；此版本尚待 Windows / Unity 2022.3 实机验收，先用临时工程。
2. 保留官方 Coplay Unity MCP `10.2.0`（官方 Git UPM 来源）。本仓库不镜像它，也不会自动升级 SDK 或 Unity。
3. ALCOM 显示预发行包后安装本包，自动补齐自有只读 `0.1.2` 和受控编辑 `0.1.0-preview.2`。受限 Bridge 必须完整注册 17 个工具，因此编辑包代码也是依赖；**安装代码不会开启权限**。
4. 本机需要 CPython **3.11+**、`uvx.exe`、Windows OpenSSH `ssh.exe`。点击自动查找或手动选 `.exe`。不接受 `py -3` 这类命令串；请选择真正的 `python.exe`。包不安装系统程序。
5. 本机预先配置 SSH 默认密钥或 ssh-agent，并人工核对服务器主机指纹。**不在聊天、窗口或工程文件保存密码/私钥内容**。监督程序使用 `BatchMode=yes`、`StrictHostKeyChecking=yes`，不会自动接受新指纹或弹密码框。密钥口令应预先加入 ssh-agent。
6. 填写直接服务器主机名/IPv4、用户名、SSH 端口和远端转发端口（默认 `28082`）。第一版明确不支持 SSH config 别名/代理命令：`-F NUL` 防止继承旧直通隧道、额外转发或 LocalCommand。主机指纹与默认用户密钥仍按 OpenSSH 用户目录读取。
7. SSH 服务端需 `GatewayPorts no`；推荐长期使用只允许所需反向转发的专用账号。窗口不会修改服务器 SSH 配置，也不能证明服务器最终绑定策略。
8. 关闭手动 Bridge 和 SSH 终端，**旧 `28080 → 18081` 直通不得恢复**。已有端口占用会失败，不会自动杀进程。既有基础 MCP 可以保留，握手验证后复用，不取得其进程所有权。

## 日常连接

窗口点击 **准备 Coplay 本地设置** 可在确认后将 Coplay 设为本地 HTTP `18081`、关闭其冷启动自动连接；这些是机器用户级 EditorPrefs，可能影响其他工程。已有 Unity HTTP 连接时先从 Coplay 窗口断开，再准备设置。连接按钮自身不会偷偷覆盖配置。

勾选本地通路确认，点击 **一键连接**：

1. 必要时由监督程序启动 `uvx --from mcpforunityserver==10.2.0 mcp-for-unity …`，显式绑定 `127.0.0.1:18081`。首次可下载运行时依赖，启动等待有上限；顶层版本固定不等于所有间接依赖已冻结。
2. 完成基础 MCP 初始化后，用 Coplay 固定版的独立 HTTP 客户端连接本工程。
3. 核对只有一个 Unity 实例、工程路径正确，启动固定 loopback 受限 Bridge；检查完整 17 工具和默认锁定状态。
4. 建立 `127.0.0.1:28082 → Windows 127.0.0.1:18082` SSH 转发，以 OpenSSH 的明确转发成功回执判断成功，不能只看进程仍活着。
5. 运行期间检查自有进程与目标工程身份；不确定时仍立即停止远端访问。导入引起的临时失联不再误报为真正换工程。

本机 `18081/18082` 是经审查的固定端口，首版不可改。管理机转发端口可改但不接受旧 `28080`。连接后 Agent 端地址为 `http://127.0.0.1:<远端端口>/mcp`；本包不会远程修改 Hermes 配置。

修改模型仍必须由操作者在原权限面板单独选择对象、精确 BlendShape 和 Preview/Apply 范围。

这里“不授权”专指本项目 Managed Editing 的 Preview/Apply 授权。Coplay 自己在首次连接时可能初始化其内置工具启用偏好；启动器不把它当作只读沙箱，也不修改或禁用所有上游工具。远端限制来自固定受限 Bridge，绝不能另开原始上游直通。

## 可选：导入／重编译后恢复连接（默认关闭）

在未连接时勾选 **“导入／重编译后恢复连接（默认关闭，不恢复编辑权限）”**，保存设置，再由你点击一次“一键连接”。仅保存选项、启动 Unity 或打开窗口不会自行建立连接。

- 只针对本次已经成功连接的工程；意图只保留在该 Unity 进程的 SessionState，退出编辑器即消失。
- 观察到导入、编译或域重载时，先撤销编辑权限并停掉旧隧道/自有连接，期间不允许远程操作。
- 等旧 Python 和 Unity 连接的清理都确认、窗口重新可用、工程路径一致且编辑器连续空闲 **5 秒**后，重新核对服务和权限锁定再恢复。
- 每次中断最多等待 **180 秒**、只自动尝试一次。恢复失败、清理失败、真正换工程或出现多实例，停止并交给操作者；不无限重试。
- **断开连接、真正关闭窗口或退出 Unity 都取消待恢复请求**。重载导致窗口暂时禁用不等于手动关闭。
- 只恢复连接，**从不恢复 Preview/Apply 租约、目标、权重方案或操作授权**。
- 未启用此项时仍按旧策略断开并等待手动连接。普通网络中断不会作为导入自动恢复，需实际观察到本地导入/重编译事件。
- `PROJECT_CHANGED` 只表示观察到不同工程/多实例；`PROJECT_UNAVAILABLE` 表示暂时无法确认（例如导入忙、超时、无实例），不能据此声称工程真的变了。

## 断开、重编译与更新

- **断开连接**、关闭连接窗口、Unity 域重载和退出：撤销本地编辑授权，写入本次唯一停止请求；停止自己启动的 SSH、Bridge 和基础 MCP。既有用户启动的基础 MCP 不停止；启动器使用自己独立的 Unity HTTP 客户端，不接管 Coplay 面板的连接；若面板已连接，请先人工断开。
- Bridge 在监督进程内运行未修改的已审查代码。先切断自有 SSH，再让 Bridge 清理精确上游会话，最后收回自有进程。会话清理有界但最坏可能数分钟。只有清理确认才允许重新启动。
- 新建的 Windows 子进程在挂起状态加入 kill-on-close Job Object 后才运行；父 Unity 退出或监督进程退出时不留下自有子进程树。崩溃不等于完成上游逻辑会话清理，不能声称每次强制退出都清理完毕。
- 异常或监督进程过早退出而未返回清理证明时，窗口保守拒绝重试。请检查诊断文件与本地进程，必要时正常退出 Unity 后重开；不要通过反复强杀/重启绕过错误。
- 更新前断开并关闭 Unity，再在 ALCOM 更新本包。**安装、更新、冷启动或单独打开窗口不会自动连接或解锁**；只有本次手动连接前已启用的恢复开关可在上述条件下恢复。
- 配置位于本机 EditorPrefs；每次运行的配置和脱敏状态在本工程 `Library/YukinoAgentLauncher/<随机ID>/`，不写 Assets/Packages。该目录含连接主机/用户名但无密码，不应公开上传。诊断不记录原始 SSH 输出或 MCP token。

## 验证边界

管理机可运行源码边界测试、实际测试子进程清理、协议模拟测试、C#9 语法及测试替身编译、真实 vrc-get 分发验证。
**这些不是 Unity 实机编译/Windows Job Object 的验收。** 发布仍为 preview，需在 Windows 实测：首次启动、复用基础服务、密钥失败/指纹失败、端口占用、编译中断、关闭窗口、Unity 退出及进程/端口回收。

原始 Coplay 保留通用工具；本地 Windows shell/管理员和修改源代码的用户不在此受限边界的威胁模型内。只关闭已知旧端口不能证明不存在其他通路。操作者必须保证只对外转发受限入口，并避免同时连接不受信任工程。
