## 这版解决什么

配套的 Hermes 宿主可以在已选工程的一次 QQ 私聊提问后，等待 **Unity 本地对这次清单的批准**，再将当前场景名、Hierarchy 第一层最多五个物体名回复到原问题。无需再发一次问题或取结果码。`agent_scene_receipt` 只返回这份清单的状态，不读取场景、不批准任务、不延长有效期。普通聊天不启动接收器，也不自动绑定工程。

- **工作站**：通过原 [VCC/VPM 订阅](https://raw.githubusercontent.com/YukinoStuki2/VRchat_Agent/vpm/index.json) 更新 `com.yukino.vrchat-agent` 到 `0.2.0-preview.6`。Coplay 仍固定 `10.2.0`。用已有备份或独立测试工程做首次验收。
- **管理端**：单独的 `vrchat-agent-hermes-0.2.0-receipt.host.1.zip` 不是 Unity 包，不要拖进 Unity。安装或启动工作站包不会部署或配置管理端。管理端由管理员限定为一个操作者的指定私聊，显式开启只读模式并提供受限传输；默认为关闭。不能向机器人发送 SSH 密码、私钥或连接凭据。
- **首次验收**：管理端就绪后，手动交付、选择工程，再问「巧克力，看看我现在打开的是哪个场景，顺便列出 Hierarchy 第一层前五个物体」。只批准本次场景/层级读取，对照 Unity 核实返回的名字。模糊或不支持的问法不会提交任务；断开、撤权或超时不自动重试。

两个分发件的精确字节已做离线配对测试；模拟私聊与本地批准，只读调用各一次，回执定位为原消息。默认及启用模式的宿主注册已在临时 profile 验证。**这不是实际 Windows Unity 导入、真实模型选工具、跨机关联或 QQ 平台送达的证明。** 包内“本地候选”是冻结时状态，不是本发布已做现场验收的声明。
